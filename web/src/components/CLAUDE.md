# web/src/components

Five panels, each a `mountXxx(root: HTMLElement, ...)` function called once from `main.ts`. No framework: each renders its markup via a template-string `innerHTML` assignment, then wires up plain `addEventListener` calls — there's no virtual DOM or reactive re-render, so a component that needs to update in response to state generally re-queries/mutates specific elements it already grabbed a reference to, rather than re-rendering wholesale.

- **`directoryBrowser.ts`** — drive `<select>` + breadcrumb + entry list. Clicking a directory calls `api.browse` again; every media row (video or audio, sharing the `entry-media` class) has a checkbox, and clicking anywhere on the row (or the checkbox itself) toggles that `Entry`'s membership in the shared `selectedMedia` store (from `../state.ts`, by `path`) rather than tracking selection locally, since `jobConfigPanel` needs to read it too. Selections persist across navigation for free since `Entry.path` is absolute. A small selection-count line + "Clear" link (`.selection-bar`) lets the user see/reset what's checked while browsing. Row highlighting/checkbox state is kept in sync by comparing against the store's current value in a `selectedMedia.subscribe` callback, not by tracking DOM node identity. The row icon is 🎬 for `entry.type === 'video'` and 🎵 for `'audio'`.
- **`jobConfigPanel.ts`** — model/language dropdowns (populated from `api.models()`/`api.languages()`), output-mode radios (toggling the custom-directory `<input>`'s `disabled` state), a collapsible advanced `-ml`/max-len field, and the submit button, which reads `selectedMedia` and fires one `api.createJob` per checked file (`Promise.allSettled`, all sharing the same model/language/output config) — a batch of more than 5 files shows as "N files selected" rather than listing every name. Each successfully created job is appended to the shared `openTabs` store as `{id, mediaName}` and the first new job becomes `activeTabId`; any per-file failures are joined into the `.form-error` div. `selectedMedia` is cleared after every submit attempt, success or partial failure, so the browser panel is ready for the next batch. Validates client-side (any file selected? model selected?) before calling the API, but the server re-validates everything anyway (see `internal/httpapi/CLAUDE.md`) — this is just for a faster/friendlier error, not the actual guarantee. `mountJobConfigPanel` returns `{ refreshModels }` (same shape as `jobHistory.ts`'s `{ refresh }`) so `main.ts` can re-fetch the model dropdown after `settingsPanel.ts` changes the models directory, without a full page reload.
- **`progressPanel.ts`** — shows one tab per entry in the shared `openTabs` store, not just a single job. Keeps a `Map<jobId, TabState>` internally (its own live status/percent/message/srtPath/error plus an `unsubscribe` for that job's `subscribeJobEvents` connection) so a backgrounded tab keeps receiving SSE updates while a different tab is frontmost — closing a tab (the tab's `×`) is the only thing that tears its subscription down. Opening a tab (from a fresh batch, or reopened via `jobHistory.ts`) does one `api.job(id)` fetch first, since SSE only pushes *new* events, not a snapshot of a job's already-existing state. `activeTabId` selects which tab's state renders into the single shared progress bar/stage/message/cancel section. The cancel button calls `api.cancelJob` — note it does *not* optimistically update the UI, it waits for the resulting `"canceled"` SSE event to actually change the displayed state. "Save" (enabled only when the active tab's job is `done`) and "Save All Completed" (enabled when any open tab is `done`) both open an inline directory picker — built from the same drive-select/breadcrumb/entry-list pieces `settingsPanel.ts` already uses for its own `kind: 'dir'` picker, reusing its exact CSS classes but not its code — and call `api.exportJob` once (Save) or once per completed tab via `Promise.allSettled` (Save All), showing a `Saved N/M — ...` summary on partial failure. This export call is additive: the `.srt` was already written to its real destination when the job finished, `exportJob` just copies it somewhere else on demand.
- **`jobHistory.ts`** — refreshes two ways: automatically whenever `activeTabId` changes (via its own subscription, which also handles the initial load), *and* via explicit `onJobCreated`/`onJobFinished` callbacks passed in from `main.ts`. The explicit callbacks aren't redundant with the `activeTabId` subscription — a job reaching a terminal state (done/failed/canceled) doesn't change *which* tab is active, so without `onJobFinished` the history list's displayed status/percent for that row would go stale until something else happened to change `activeTabId`. Clicking a row opens (or refocuses, if already open) that job's Progress tab: if its id isn't already in `openTabs`, it's appended (labeled via `basenameOf` on the job's media path) before `activeTabId` is set to it.
- **`settingsPanel.ts`** — four text inputs (ffmpeg.exe / whisper-cli.exe / models directory / default media directory, labeled "Default Media Directory" but still backed by the `defaultVideoDir` field on the wire and in `settings.json` — deliberately not renamed, since it's an on-disk persisted setting and renaming its JSON key would silently drop an existing user's saved override on upgrade) overriding the conventional `bin/ffmpeg`/`bin/whisper`/`models` defaults (see `internal/config`'s `Effective*` methods; the default media directory has no conventional-default fallback, it's just "" until set), each with a "Browse" button opening a small inline picker built from the same pieces as `directoryBrowser.ts` (drive select + breadcrumb + entry list) but **not sharing code with it** — deliberately, matching this directory's existing pattern of self-contained panels rather than introducing a shared abstraction for one reuse. The picker's behavior differs by `kind`: `'exe'` (ffmpeg/whisper-cli fields) is click-a-file-to-select, same interaction as picking a media file; `'dir'` (the models/default-media-dir fields) has no file to click, so it shows an explicit "Select This Directory" button that selects whatever directory is currently being browsed. "Save Settings" PUTs all four fields at once (`api.updateSettings`); "Reset to Default" PUTs all four as `""`, which `internal/httpapi`'s tri-state request handling treats as "clear this override" rather than "leave unchanged" (see `internal/httpapi/CLAUDE.md`). Either button's `onSaved()` callback (wired in `main.ts`) re-runs the health check and `jobConfigPanel`'s `refreshModels()`.
- `directoryBrowser.ts` also reads `api.settings()` on load — if `defaultVideoDir` is set, it opens straight to that directory (and selects the matching drive in the dropdown) instead of defaulting to the first drive.

If you add a sixth panel, follow the same shape (a `mountXxx` function, own file, reads/writes `../state.ts` for anything cross-panel) rather than introducing a different pattern.
