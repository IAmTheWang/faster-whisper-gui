# web/src

No framework — see [components/CLAUDE.md](components/CLAUDE.md) for the five UI panels. This directory holds the shared plumbing they're built on:

- **`api.ts`** — typed `fetch` wrapper mirroring the Go backend's JSON shapes (`Job`, `Model`, `Listing`, `SettingsPaths`, etc. — keep these in sync with the corresponding Go structs in `internal/job`, `internal/transcribe`, `internal/fsbrowse`, `internal/httpapi`'s `settingsResponse` if the API changes) plus `subscribeJobEvents`, which wraps `EventSource` for a job's SSE stream. `browse(path, kind)` takes an optional `BrowseKind` (`'media'` default, `'exe'`, `'dir'`) matching `internal/httpapi`'s `handleBrowse` — `directoryBrowser.ts` relies on the default, `settingsPanel.ts`/`progressPanel.ts` pass `'exe'`/`'dir'` explicitly. `exportJob(id, destDir)` posts to `/api/jobs/{id}/export` — a job must already be `done`; it copies that job's already-written `.srt` into `destDir` as an additional, on-demand save, it does not change where the original was written. **The server's custom `"error"` named SSE event unavoidably shares a name with `EventSource`'s own built-in connection-failure event.** The fix here is checking `typeof (e as MessageEvent).data === 'string'` — a genuine server-sent `"error"` event always carries a JSON string payload, a native transport error doesn't. Don't try to fix this by having the browser ignore the collision differently; if the wire event name ever changes, update it on both sides (see `internal/httpapi/CLAUDE.md`).
- **`state.ts`** — `Store<T>`, a ~20-line pub-sub cell (subscribe gets called immediately with the current value, then again on every `set`). `selectedMedia` (checked-but-not-submitted media files), `openTabs` (jobs currently shown as a Progress tab, each carrying `{id, mediaName}`), and `activeTabId` (which tab is frontmost) are the pieces of state shared across panels; add more here rather than reaching into another component's internals.
- **`dom.ts`** — `escapeHtml`, used wherever a component interpolates a filesystem-derived string (filename, path) into an `innerHTML` template string. Windows filenames can't actually contain `<`/`>`, so this isn't defusing a realistic injection on this platform — it's cheap insurance against `&` breaking entity parsing and against relying on that platform detail at all. `basenameOf(path)` extracts a filename from a Windows- or forward-slash path — used by `jobHistory.ts` when reopening an old job as a Progress tab (a freshly-created job already has the video's `Entry.name` in hand and doesn't need it).
- **`main.ts`** — wires the five panels together plus the health-check banner (`api.health()` on load, shown/hidden based on whether ffmpeg/whisper-cli probed OK).

There's no build step for this directory beyond what Vite/tsc already do — no bundler config, no path aliases, plain relative imports throughout.
