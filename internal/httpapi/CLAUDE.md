# internal/httpapi

The REST + SSE surface, layered on top of `internal/job`, `internal/fsbrowse`, `internal/transcribe` (for model listing/health checks), and `internal/config`. `Server` (in `server.go`) just holds those dependencies; `RegisterRoutes` (`router.go`) wires them onto a `*http.ServeMux` using Go 1.22+'s method+pattern syntax (`"POST /api/jobs"` etc.) — it does *not* create its own mux or start listening, `internal/appserver` owns that.

File-by-file:

- **`middleware.go`** — `WithMiddleware` (logging + panic recovery). Applied by `appserver` around the *whole* top-level mux (API + embedded static files), not just these routes, so a panic anywhere still gets a clean 500.
- **`respond.go`** — `writeJSON`/`writeError(Msg)` helpers. Use these, don't hand-roll `json.NewEncoder` in a new handler.
- **`health_handlers.go`**, **`browse_handlers.go`**, **`models_handlers.go`** — thin wrappers calling straight into `transcribe`/`fsbrowse` and JSON-encoding the result.
- **`job_handlers.go`** — `handleCreateJob` is the interesting one: it validates the *entire* request before enqueueing anything — `fsbrowse.ValidateVideoFile`, then output-dir validation if `outputMode == custom`, then model lookup, then `job.OutputPrefix` + `fsbrowse.EnsureWritable` on the computed `.srt` path — and only calls `Queue.Submit` if all of that passes. The point is failing fast on a bad request instead of discovering the problem after a multi-minute transcription. If you add a new failure mode to the pipeline, check whether it can be validated here up front rather than surfacing only as a job failure.
- **`sse_handlers.go`** — `GET /api/jobs/{id}/events`. Two things worth knowing before touching this: (1) it sends the job's *current* state immediately on connect (`sseEventFromJob`), so a client that connects after the job already finished still sees the right terminal state instead of hanging forever waiting for an event that already happened; (2) it explicitly clears the response's write deadline via `http.NewResponseController(w).SetWriteDeadline(time.Time{})` and sends a heartbeat comment (`: heartbeat\n\n`) every 15s. There's no server-wide `WriteTimeout` set (see `internal/appserver`/root CLAUDE.md), so the explicit clear here is currently redundant *in this codebase* — but if anyone ever adds one for "hardening", this handler needs the override or long transcriptions will get their SSE connection cut mid-stream. The server's own custom `"error"` SSE event name collides with `EventSource`'s built-in connection-failure event on the frontend — see `web/src/api.ts`'s `subscribeJobEvents` for how that's disambiguated; don't rename the wire event to "fix" it without updating that too.

The server binds `127.0.0.1` only (set in `internal/appserver`, not here) — every handler in this package assumes that and returns real filesystem paths without further access control.
