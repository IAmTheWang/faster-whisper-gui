# internal/transcribe

The media (video or audio) → wav → srt pipeline pieces. Everything here shells out via `internal/procutil` — never cgo, see that package's CLAUDE.md and the root one for why (no C/C++ toolchain to build this repo with, a whisper-cli crash can't take the Go process down, swapping CPU/CUDA builds is just swapping files in `bin/whisper/`).

- **`engine.go`** — the `Engine` interface (`Transcribe(ctx, Options, onProgress) error`) and its `Options`/`Progress` types. This is the extension point for a hypothetical future faster-whisper-as-subprocess engine — `internal/job`'s queue only depends on this interface, not on `WhisperCppEngine` directly, so a second implementation could be swapped in without touching the queue.
- **`whispercpp.go`** — `WhisperCppEngine`, the only current `Engine` implementation. `BuildWhisperArgs` is a pure function (easy to unit test) building the `whisper-cli` argv; language defaults to `"auto"` if empty. `Transcribe` reads stdout and stderr concurrently through `procutil.NewCRLineScanner`: **stdout's per-segment timestamps are the primary progress signal** (end-timestamp ÷ `Options.TotalDuration`), stderr's own `progress = NN%` line is only a secondary/supplementary one, because whisper.cpp's own percentage reporting has real documented reliability problems (a divide-by-zero SIGFPE, progress appearing stuck on long files) — don't flip this priority. `CliPath` is `func() string`, not a plain string — the one `WhisperCppEngine` instance is constructed once in `internal/appserver` and reused for every job, so a plain string would freeze whatever path was configured at process startup; `appserver` wires it to `(*config.Config).EffectiveWhisperCliPath`, a method value, so a Settings-panel change takes effect on the very next job with no restart needed. `BuildWhisperArgs` always appends `-mc <Options.MaxContext>` (unlike `-ml`, which is only added `if opts.MaxLen > 0`) because `Options.MaxContext`'s Go zero-value (`0`) *is* the desired default here, not "unset" — whisper.cpp conditions each segment's decoding on all previously transcribed text by default (its own native `-mc` default is `-1`, unlimited), so one bad segment (typically triggered by silence, music, or background noise) can otherwise keep reinforcing itself for the rest of the file; defaulting to `-mc 0` disables that carryover so a single bad segment can't propagate.
- **`ffmpeg.go`** — `ExtractAudio` (media → 16kHz mono 16-bit PCM WAV; whisper.cpp cannot read video/audio containers directly, this is why ffmpeg is a required external dependency at all) and `ProbeDuration` (the exact `ffprobe -show_entries format=duration -of default=noprint_wrappers=1:nokey=1` incantation that makes it print a bare float to stdout, parsed with `strconv.ParseFloat`) — `format=duration` reads the container-level duration, so it works the same whether the input has a video stream or is audio-only. `ExtractAudioArgs`/`ProbeDurationArgs` are separated out as pure functions purely for testability — actual subprocess invocation isn't unit-tested, only argv construction.
- **`health.go`** — `CheckFfmpeg`/`CheckWhisperCli`, used by `GET /api/health` so a missing binary or DLL surfaces as a clear frontend message before a user submits a real job, not after. Short timeout (`healthCheckTimeout`), and note it doesn't special-case a missing-DLL failure — any non-zero exit or start failure just gets its stderr tail (or the raw error) surfaced as-is.
- **`models.go`** — `ScanModels`, a non-recursive scan of `models/` for `ggml-*.bin` files. Manual-placement only for now (see root README's "known limitations") — no download/checksum logic.

If you add a second `Engine`, it needs its own progress-derivation strategy; don't assume every future engine prints whisper.cpp-shaped stdout.
