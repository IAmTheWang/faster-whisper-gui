# internal/job

The job queue and state machine. Three files:

- **`job.go`** — `Status`/`OutputMode` enums, the `Request`/`Job` structs (with JSON tags for the API — `Request.ModelPath` is `json:"-"`, it's a local filesystem detail not part of the public shape), and `Store`, an in-memory thread-safe job history.
  - **`Store.Get` returns a value copy of `Job`, never the live `*Job`.** The worker goroutine mutates a job's fields in place under `Store`'s lock (`Update`); handing back the pointer instead of a copy would let a caller read it concurrently with no synchronization. If you add a new `Store` method, keep this invariant — copy out, don't leak the pointer.
  - **`Store.Cancel` checks `Status.IsTerminal()` and reads the cancel func together, under one lock**, before deciding whether to invoke it. This was a real bug once: an earlier version only checked "is there a cancel func at all" (true forever once a job starts, even after it finishes), so canceling an already-done job incorrectly succeeded (202 instead of 409). If you touch `Cancel`, keep the terminal-status check inside the same critical section as the read of `j.cancel`, not after — otherwise it races `Update` marking the job terminal.
- **`queue.go`** — `Queue` runs exactly one job at a time (a single GPU can't usefully run concurrent whisper-cli processes anyway) via one worker goroutine consuming a channel. `Pipeline.ExtractAudio`/`Pipeline.ProbeDuration` are **injected function fields**, not direct calls to `transcribe.ExtractAudio`/`transcribe.ProbeDuration` — this is deliberate so `queue_test.go` can fake them and test sequencing/cancellation without spawning real ffmpeg/whisper-cli processes. `main.go`/`appserver.go` wire the real `transcribe` functions in; don't collapse this back to a direct dependency just to "simplify" it, the tests rely on the seam.
- **`outputpath.go`** — `OutputPrefix(req)`, the pure function computing whisper-cli's `-of` argument: the video's own directory + basename by default, or `OutputDir` + basename in custom mode, with only the *final* extension stripped (so `my.video.v2.mp4` → `.../my.video.v2`, not `.../my`) and both the video path and any custom output dir normalized via `filepath.Clean(filepath.FromSlash(...))` first. This is exported (not just package-private) specifically so `internal/httpapi`'s job handler can compute the same `.srt` path for the pre-submission writability check — keep it a pure function if you extend it, `httpapi` depends on that.

`EventPublisher` is an interface `job` defines itself (not imported from `sseutil`) purely to avoid `job` depending on the SSE transport — `sseutil.Broker` satisfies it structurally. If you need a second event sink (e.g. logging), implement this interface rather than reaching into `sseutil` from here.
